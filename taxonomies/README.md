# taxonomies/

Controlled vocabularies as pure data, plus the precomputed text embeddings
that let a client score against them without downloading a text model.

| File | What it is |
|---|---|
| `<name>.yaml` | The taxonomy: axes of terms, each with the prompt phrase that forms its candidate text. Validated against `schemas/taxonomy.json`. |
| `<name>.embeddings.json` | Default-tier artifact: one label vector per term, plus the model's learned sigmoid calibration. |
| `<name>.<tier>.embeddings.json` | Same, for another model tier. |

## Why the embeddings are committed

`taxonomies/asset-tags.yaml` is scored by SigLIP-2 on the user's own device
(SBAI-7726). SigLIP is two towers: one encodes the image, one encodes each
candidate label. The label side never changes between assets, so encoding it
on-device would mean shipping a 283 MB - 1.1 GB text model to recompute the
same 85 vectors forever.

Precomputing collapses that: the device downloads the **vision tower only**
(55-95 MB for the base tier) and dot-products against these vectors. That is
the entire reason the on-device tagger fits in a free tier.

## What the artifact must carry

Vectors alone are not enough. SigLIP turns a similarity into a probability with
two learned scalars:

```
score = sigmoid(logit_scale * dot(unit(image_embed), unit(text_embed)) + logit_bias)
```

Those live in the original checkpoint (`logit_scale` is stored in **log space**;
the model applies `exp()` to it), not in the split ONNX graphs, so the generator
reads them out of the checkpoint's safetensors and stamps them here. Without
them the device has raw cosine similarities in roughly `[-0.1, 0.3]` and every
threshold in the product is arbitrary.

## Reading the scores

Do **not** treat the probability as a standalone accept/reject cut. SigLIP's
sigmoid is calibrated for retrieval against *specific captions*, while a
taxonomy is deliberately generic. Measured against the HF PyTorch reference on
the same image, `"a photo of 2 cats."` scores `p=0.4639` while
`"a photo of an animal."` scores `p=0.0003` — the ranking is right, the
absolute number is small. A 0.5 (or 0.3) cut tags nothing, ever.

The artifact therefore ships the policy next to the calibration:
`default_top_k_per_axis` (rank within each axis, keep the top k) and
`default_threshold` (a floor that drops an axis matching nothing).

## Regenerating

```bash
pip install onnxruntime huggingface_hub transformers numpy pyyaml

# after editing terms/prompts -- restamps content_hash
python3 scripts/generate_taxonomy_embeddings.py --update-hash

# per tier
python3 scripts/generate_taxonomy_embeddings.py --tier base
python3 scripts/generate_taxonomy_embeddings.py --tier so400m

# no download; just show the composed candidate texts
python3 scripts/generate_taxonomy_embeddings.py --print-labels
```

Not run in CI — the artifacts are committed and regenerated by hand per
taxonomy revision. `scripts/validate.py` fails the build if a taxonomy's
`content_hash` no longer matches its axes, or if any artifact's stamp, label
order, or vector width has drifted from the taxonomy it names.

## Adding a tier

Tiers are **not** interchangeable: base embeds at 768 dims, so400m at 1152.
Add an entry to `TIERS` in `scripts/generate_taxonomy_embeddings.py`
(ONNX repo, text graph, calibration repo, artifact suffix), regenerate, and
point the matching catalog weight row's `taxonomy_embeddings` at the new file.
